# Anatoly Tsar — сайт тату-мастера

Личная визитка мастера: тёмная атмосфера, крупные фотографии, сдержанная типографика и прямой путь к разговору.

## Как посмотреть

Статический сайт без сборки: `index.html`, `style.css`, `app.js`, `assets/`. Локально: `python3 -m http.server` в этой папке и открыть http://localhost:8000.

Автономный файл (всё встроено в один HTML, удобно переслать): `python3 build.py . ../anatoly.html`.

## Публикация (GitHub Pages)

1. В репозитории: Settings → Pages → Source «Deploy from a branch», ветка `main`, папка `/ (root)`. Сайт: https://arbacat.github.io/tatto_Anatoly_page/. Если после пуша сайт не обновился — пересобрать: `gh api -X POST repos/ArbaCat/tatto_Anatoly_page/pages/builds`.
2. Свой домен: у регистратора добавить для корня домена A-записи `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`, для `www` — CNAME на `arbacat.github.io`. Затем Settings → Pages → Custom domain → домен (GitHub добавит файл `CNAME`), дождаться проверки DNS и включить «Enforce HTTPS».
3. После смены адреса заменить `https://arbacat.github.io/tatto_Anatoly_page/` в `index.html` (canonical, og:url, og:image, JSON-LD). Превью в Facebook/Messenger обновить через Sharing Debugger.

Одно главное действие — «Napísať Anatolymu»: сразу открывает WhatsApp `+421915317473` с текстом «Ahoj Anatoly, páči sa mi tvoja práca. Chcel/a by som sa s tebou poradiť ohľadom tetovania.» (человек может его изменить и отправляет сам). Рядом — компактная кнопка Instagram (`ig.me/m/anatoly.tattoo`, открывает личные сообщения). Facebook — только тихая ссылка внизу. Формы нет, сайт ничего не отправляет и не хранит, записи не подтверждает.

Кнопка одинаковая в шапке, на первом экране, в «O mne», в финальном блоке, в меню и в нижней панели на телефоне. В детальном просмотре работы — «Chcem niečo podobné»: тот же WhatsApp с текстом «…ohľadom podobného tetovania.» и ссылкой на фото этой работы (приложить файл через ссылку `wa.me` нельзя — только текст).

Все ссылки стоят прямо в `index.html` и работают без JS. Сайт личный: названия, почты и адреса студии на нём нет, из местоположения только город (Banská Bystrica).

## Работы (портфолио)

Источник — `data/works.json`: работы по порядку (первая показывается первой) с полями `photo`, `title`, `category`, `description`, `alt`, `crop`. Из него `scripts/build_works.py` пишет в `index.html` список `<ul id="work-list">`, первую работу, её подпись и счётчики; крупная работа, подписи и детальный просмотр строятся из списка. Этот кусок `index.html` руками не править — перезапишется.

Скрипт же готовит фото. Новое (не JPEG, с EXIF, больше 2560 px или со сложным именем) он поворачивает по EXIF, переводит в sRGB, уменьшает до 2560 px по длинной стороне, убирает метаданные (в том числе GPS) и переименовывает по названию работы в `assets/works/<slug>.jpg`; новое имя записывает обратно в `works.json`. Потом делает `assets/works/sizes/<name>-480.jpg` (миниатюры) и `-960.jpg` (телефоны); оригинал грузится в детальном просмотре. `crop` — куда смотрит кадр миниатюры 4 : 5: `50% 30%` — чуть выше центра, пусто — центр.

Вручную: `pip install pillow pillow-heif`, поправить `data/works.json`, выполнить `python3 scripts/build_works.py`.

## Админка (Pages CMS)

Анатолий сам добавляет и правит работы в [Pages CMS](https://app.pagescms.org) — с телефона или компьютера, без аккаунта на GitHub. Поля описаны в `.pages.yml` (подписи по-русски, тексты для сайта — по-словацки). Каждое сохранение — коммит в `main`; `.github/workflows/works.yml` запускает `build_works.py`, коммитит результат, и GitHub Pages его публикует. От сохранения до сайта — 2–3 минуты. Если в списке ошибка (нет фото или названия), Action падает, сайт остаётся прежним, а GitHub присылает письмо владельцу репозитория.

Настроить один раз:

1. Войти на [app.pagescms.org](https://app.pagescms.org) через GitHub и установить приложение Pages CMS только на этот репозиторий.
2. Открыть репозиторий в Pages CMS и пригласить Анатолия по почте (Collaborators). Он входит по ссылке из письма и видит раздел «Работы».

Убранная из списка работа пропадает с сайта; файл фото остаётся в `assets/works/` (его можно удалить в разделе Media).

Геоданные: фото с телефона сначала попадает в репозиторий как есть, и GPS скрипт убирает только следующим коммитом. Репозиторий публичный, так что исходный файл с координатами остаётся в истории git. Чтобы координаты студии туда не попадали, у Анатолия на телефоне стоит выключить геолокацию для камеры (iPhone: Настройки → Конфиденциальность → Службы геолокации → Камера → Никогда).

Правила отображения: миниатюры — 4 : 5 с управляемым кадрированием; крупная работа и детальный просмотр — фото целиком, без обрезки и затемняющих градиентов; формы прямоугольные. В детальном просмотре грузится оригинал: увеличение кликом, кнопкой-лупой, колесом и клавишами `+` / `−` / `0`; на телефоне — двойной тап и щипок; увеличенное фото двигается перетаскиванием или стрелками.

## Дизайн-система

В начале `style.css`: цвета (фон, поверхности, основной и вторичный текст, золотой акцент, линии), шкала шрифта (13 / 14 / 16 / 18 px, заголовки работ 20–24, разделов 30–46, главный 36–64), отступы 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96. Кнопки: `.btn--primary` (золотая заливка, главное действие), `.btn--secondary` (контур), `.text-link` (текстовая ссылка), `.round` (управление галереей), `.icon-btn` (компактный Instagram). Иконки — SVG-спрайт в начале `index.html`, у каждой одно значение: сообщение, Instagram, внешняя ссылка, увеличить / уменьшить, влево / вправо / вниз, закрыть. Анимации короткие; при «уменьшенном движении» отключаются.
